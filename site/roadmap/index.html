Product direction

Build the boundary before expanding the surface.

Direction, not a release promise. Three-level nested shared workspaces shipped in v0.0.9. Searchable, versioned native-text PDF artifacts are now a default-off production opt-in; Word documents follow only after the PDF processing boundary is proven.

Available now

The alpha has shipped and remains deliberately focused.

The current alpha stays deliberately bounded. Work remains concentrated on security, correctness, release readiness, documentation, and deliberately scoped format slices.

  • HTML, Markdown, and MermaidPreserve, search, version, and share artifacts through authenticated personal and shared workspaces.
  • Visible page hierarchyThe Library, Overview, page detail, and MCP expose authorization-filtered parent and child context within one workspace.
  • Normalized raster imagesPNG/JPEG uploads cross an isolated parser boundary and retain only re-encoded pixels.
  • Opt-in searchable PDFsNative-text PDFs retain private originals, extract bounded untrusted text in a dedicated processor, and use native artifact-origin viewing.
  • Nested shared workspacesRoot, child, and grandchild workspaces preserve exact content boundaries while parent authority flows through explicit inheritance rules.
  • Isolated HTML executionGenerated HTML runs on the separate artifact origin under the documented iframe, CSP, and signed-preview boundary.
  • Scoped MCP accessNine operations cover workspace discovery, taxonomy, search, read, create, update, and revert without granting preview capabilities.
Workspace libraries stay exact

Nested membership can grant authority downward, but selecting a parent never merges descendant pages, categories, storage counters, Library filters, or selected MCP scopes.

Shipped in v0.0.7

Narrow external sharing is available.

Expiring and one-time links now use the documented bearer-capability boundary. ArtifactFlow stores only a hash of the random secret, reveals only the selected page, re-checks live state on every load, consumes one-time links atomically, and keeps executable HTML on the isolated artifact origin.

This is intentionally not broad public hosting: there is no public navigation, search, reusable unlimited link, recipient account, or workspace disclosure.

Shipped in v0.0.9

Nested shared workspaces, capped at three levels.

Inherited authority

Parent memberships flow downward by default. A child can disable inheritance at its boundary or exclude one inherited user locally while independent direct roles remain effective.

Bounded hierarchy

Root, child, and grandchild workspaces remain distinct page, category, storage, and Library boundaries. Reparenting prevents cycles, preserves exact MCP scopes, and revokes lost preview and realtime access.

Implemented, verified, and released

The server, PostgreSQL concurrency, authorization non-disclosure, and multi-engine browser proof is included in the released v0.0.9 line.

Document formats

Searchable PDF is opt-in; Word follows.

Searchable PDF artifacts

Native-text PDFs join the permission-aware catalog and version history with private originals, bounded isolated extraction, browser-native viewing on the existing cookieless artifact origin, normal forced-attachment downloads, and proof that restricted content never leaks. Preview deliberately transfers the authorized original. Embedded text remains untrusted and may not be visible in the document. OCR remains a later PDF milestone.

Searchable Word documents

Modern DOCX files would keep their private original, extracted searchable text, safe non-executable preview, and immutable replacements under strict ZIP and parser limits.

Before PDF production enablement

Scheduling follows proof, not the other way around.

  1. Write the product rule and architecture decision before changing schema or authorization behavior.
  2. Update the threat model and identify the information each new boundary could expose.
  3. Implement tests first, including authorization failures, concurrency, revocation, storage cleanup, and browser-level isolation.
  4. Pass the repository's static analysis, test, security, build, image, and release gates before presenting the work as available.

Explicitly not promised

A candidate is not a date, order, or commitment.

  • No target datesThe roadmap does not promise a release date or quarter for candidate work.
  • No guaranteed orderingFeedback and security findings may change priorities before a candidate is scheduled.
  • No built-in AI generationArtifactFlow preserves deliberate artifacts; it is not becoming an AI generation platform.
  • No broad public hosting productScoped external links are a candidate boundary, not a public marketplace or anonymous artifact-hosting service.
  • No automatic enterprise expansionSSO, a full approval system, and a broad enterprise RBAC suite remain outside the current roadmap.
